# ADR-001 —— 总体技术选型

> 状态：已采纳（保持阶段 00 决策不变）
> 日期：2026-08-13

## 标题

采用「模块化单仓库（Monorepo）+ Next.js + PostgreSQL(pgvector) + Drizzle + Redis/BullMQ + 独立 Worker + AI Provider 抽象」构建 FinanceHot MVP。

## 背景

FinanceHot 是 AI 驱动的全球财经情报过滤器，链路为「采集 → 解析 → 翻译 → 过滤 → 去重 → 聚类 → 评分 → 摘要 → 展示」，同时有前台与后台、实时异步处理、多语言、向量去重/聚类等需求。总控包要求"不为技术先进无意义拆微服务，MVP 保持可维护的模块化单仓库"。

## 决策

1. **Monorepo（pnpm + Turborepo）而非微服务**：单团队、单部署单元，复用 db/ai/crawler/ui 包，边界靠包职责而非进程数量；Worker 仅作为独立进程拆分（异步所需），不算微服务化。
2. **Drizzle 而非 Prisma**：核心原因是 pgvector 原生支持、PostgreSQL FTS/trigram/窗口函数/复杂查询的 SQL 控制力、drizzle-kit 生成的 SQL migration 可审查、轻量无运行时代码生成。代价是生态较年轻，复杂 relation 需手写——本项目多对多用显式关联表，风险可控。
3. **BullMQ 而非自建队列**：成熟，支持重试/退避/failed set/分布式锁，避免重复造轮子。
4. **Node.js 爬虫优先**：RSS 与轻量网页解析足够；复杂解析确有必要再引 Python Worker，避免过早引入双语言运维负担。
5. **AI Provider 抽象 + zod Structured Output**：厂商/模型不写死（.env 配置）；所有 AI 输出走 JSON Schema 校验，禁止自由文本解析；Embedding 独立 Provider + pgvector。

## 基础设施约束（阶段 01–02 已落实）

- PostgreSQL 容器必须使用**含 pgvector 的镜像**（如 `pgvector/pgvector:pg16`），普通 `postgres:16` 不含 pgvector。
- Drizzle migration 首步必须执行：
  - `CREATE EXTENSION IF NOT EXISTS vector;`
  - `CREATE EXTENSION IF NOT EXISTS pg_trgm;`

## 影响

后续所有阶段围绕此架构开发；如需引入 Python Worker 或更换 ORM/队列，须先做架构评审并更新本 ADR。
