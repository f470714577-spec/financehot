# ADR-002 —— Article/Event 关系、Embedding 持久化与评分/搜索/队列语义

> 状态：已采纳；阶段 02 已落实数据模型约束，阶段 08–10 的 AI、Embedding、队列与事件关系实现按本 ADR 收口
> 日期：2026-08-13
> 触发：阶段 00.1 架构修订指令（第 2、3、5、6、7、8、10、11、12 部分）

## 决策 1：Article↔Event 用 event_articles 单一权威，移除 articles.event_id

**决策**：`event_articles` 多对多作为 Article↔Event 的**唯一权威事实源**，扩展字段 `is_primary` 标记主报道；`articles` 表**不保留**任何 event 外键字段（原 `event_id` 移除）。

**备选方案**：`event_articles`（权威）+ `articles.primary_event_id`（冗余快速引用）。

**选择理由**：

- 单一事实源，无"articles.primary_event_id=A 而 event_articles 里 primary=B"的事务一致性负担。
- `event_articles.is_primary` 已可表达"主事件"语义。
- 前台详情页是单篇查询，join `event_articles` 一次即可，无需冗余字段；列表页主展示 Event 而非 Article，本就不需要 article→event 的反向快速引用。
- 不以"避免 N+1"为理由维护重复事实源——本场景不存在该收益。
- 数据库阶段为 `is_primary` 加 **Partial Unique Index**：`(event_id) WHERE is_primary = true`，保证同一 event 最多一条主报道。

## 决策 2：raw_articles 与 articles 为 0..1，允许无 Article 产物

**决策**：`raw_articles` 不强制 1:1 `articles`。一篇原始抓取可能：

- 正常转换 → Article（`article_id` 指向产物）
- 非财经/噪声 → `processing_status = filtered_out`，`rejected_reason` 记录原因
- 重复 → `processing_status = duplicate`，`duplicate_of_article_id` 指向被重复对象
- 解析失败 → `processing_status = failed`

新增字段：`processing_status`、`article_id`(可空 FK)、`rejected_reason`、`duplicate_of_article_id`(可空 FK)、`parser_version`。

**理由**：原始快照尽量保留，支持重新解析、排错、统计过滤率、重跑算法；同一 URL 未来可重新抓取形成多个 raw 快照。

## 决策 3：Embedding 持久化到 article_embeddings

**决策**：新增 `article_embeddings` 表，Article↔Embedding 为 **1:N**，字段含 provider、model、dimensions、embedding、input_hash、embedding_version；**唯一约束 `(article_id, provider, model, input_hash, embedding_version)`**。

**理由**：Embedding 不是临时变量，必须能回答"哪个 Provider/Model 生成、维度多少、基于哪一版输入、内容变化后是否需重新生成"；唯一约束保证同一版本不重复生成、同一输入不同 model 可并存。

**边界**：MVP 不强制 Event 级 Embedding（后续可对称扩展 `event_embeddings`）。当前混合 dimensions 表只做 pgvector 精确 cosine 查询，不建立 HNSW/IVFFlat；统一维度后再单独评估 ANN 索引。

## 决策 3.1：Embedding Provider 与 LLM Provider 分离

**决策**：Embedding 使用独立 `EmbeddingProvider`，当前协议为 OpenAI-compatible `/embeddings`。配置缺失必须保持 `unconfigured`，Worker 可启动且不发请求；401/403 不重试，429/5xx/timeout/network 只做有限重试，响应必须通过有限数向量和 dimensions 校验。

**理由**：Embedding 与 LLM 的模型、维度、成本和缓存生命周期不同；分离后可以在不影响 Article AI 流水线的情况下替换向量供应商，并保证非法向量不会污染 pgvector。

## 决策 3.2：保守、可追溯的 Article→Event 聚类与纠错

**决策**：阶段 09/10 只处理非隐藏且阶段 08 `entity_extracted` 的 Article。输入固定为规范化 `title_zh + "\\n" + summary_zh`；候选必须满足相同 provider/model/version/dimensions、72 小时窗口，并通过分类、已抽取实体、标题特征和动作冲突保护。高置信候选直接合并；边界候选才调用版本化结构化 LLM。LLM 未配置、请求失败或输出不通过 `JSON.parse`+Zod 时保守创建新 Event。`event_articles` 是唯一关系事实源；主报道、标题摘要、Event 计数与首末时间在同一事务内维护，事实不足不自动标记 `confirmed`。

**并发与幂等**：Embedding 任务以 Article、输入哈希、Provider、Model、版本作为唯一缓存边界；聚类、merge、split 均使用事务级 advisory lock，重复任务通过缓存、唯一关系与确定性成员集合短路，避免双 Worker 竞争产生重复调用、重复关系或孤儿 Event。merge/split 不暴露 Admin 入口；split 必须给出明确成员集合，不得静默丢 Article。

**展示**：首页以 Event 为主展示对象，Article 详情入口保留；Event 详情展示状态、时间线和多信源数量。信源按 `source_level`、可信度和发布时间降序优先，确保“另有 X 家信源报道”来自关系事实而非文章列表猜测。

## 决策 4：评分权威层级，取消 article.heat_score

**决策**：

- Article Finance Score = 单篇新闻重要性。
- Event Finance Score = 事件整体重要性（成员 Article 聚合 + 事件级修正）。
- **Heat Score 以 Event 为唯一权威对象**。
- **取消 article 级 heat_score**。

**理由**：Heat 的全部计算维度（报道媒体数、增速、高质量源数、国家多样性、重复报道增速）均为事件聚合维度，单篇文章无独立"热"语义；保留只会制造与 Event Heat 不一致的第二事实源。

**派生字段说明**：`events.article_count`/`source_count` 为**派生缓存字段**，由 `event_articles` 聚合而来；聚类/合并/拆分操作在**同一事务**内重算更新，后台提供重算校验接口。事实源是 `event_articles`。

## 决策 5：中文搜索用 pg_trgm，P0 不承诺证券搜索

**决策**：MVP 搜索按内容分策略——中文标题/摘要用 **pg_trgm**（substring/similarity）；英文用 **PostgreSQL FTS**；Ticker 用 **exact/prefix**；公司别名用 **alias + trigram**。初始化预留 `CREATE EXTENSION IF NOT EXISTS pg_trgm;`。

**边界**：P0 只实现基础新闻/事件搜索；证券 Ticker / A股 / 港股 / 美股 / 公司证券关联搜索属 **P1 阶段 17**，P0 预建 `securities` 表但**不承诺** Ticker→Article 搜索能力，验收标准不得提前要求。

## 决策 6：BullMQ 失败语义，不虚构独立 DLQ

**决策**：MVP 不实现专门 DLQ。失败处理 = BullMQ **failed set** + `ai_tasks`/`crawl_tasks` **持久化失败状态** + **Admin 后台重跑**。未来确有需要再增加专门 DLQ。

## 决策 7：Package 低耦合依赖

**决策**：`shared` 为唯一基础层；`db`/`ai`/`crawler`/`ui` 均仅依赖 `shared`；`crawler` 不依赖 `ai` 与 db ORM；`ai` 不依赖 `crawler` 与 db；`crawler`/`ai` 输入输出 DTO；**持久化与工作流编排由 `apps/worker` 完成**；`apps/web` 可执行短事务 CRUD 与任务入队，但禁止在 HTTP 请求内执行 Crawler、LLM、Embedding、Event Cluster 等耗时流水线。

## 影响

- 阶段 02：只建 P0 表（20 张，含 article_embeddings、article_categories、event_topics）；P1 表（8 张）不落库，阶段 17/18 再建；articles 无 event_id、无 heat_score。
- 阶段 07/08/09：状态机含 FILTERED_OUT/DUPLICATE/FAILED/EMBEDDED/CLUSTERED；BullMQ 用 failed set。
- 阶段 11：Heat 只算事件级。
- 阶段 17：证券搜索才启用。
